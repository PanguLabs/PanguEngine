# ECS 首版与 World 生命周期实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以 C 编译 flecs 运行库，交付使用其原生 C++ API 的 Pangu ECS，贯通组件登记、World 推进与宿主先排空 World 再卸载模块的流程。

**Architecture:** 应用显式接纳可选常驻 `Pangu::ECS`，每个 World Scope 持有一个 ECS 实例。EngineHost 关闭业务接纳，借助现有 Scope 清理器排空 World，再进入 Module 和 Log 的既有关闭阶段。正式无窗口 Project 同时消费 ECS 和业务 Module，并验证动态库之间的类型绑定及卸载顺序。

**Tech Stack:** CMake 4.0+、Ninja、Clang、C++23（无异常、保留 RTTI）、flecs v4.2.0 的 C 核心、PanguMetaTool、GoogleTest、CTest。

**Spec:** [ECS 首版：flecs 原生接口与 World 生命周期](../specs/2026-11-17-ecs-world-design.md)

## 全局约束

- 固定 flecs `v4.2.0` 的提交 `6566d4b7bdc597d0b74d5e0a4104d4ae6ac49402`，正式源码来自 `Source/ThirdParty/Flecs/Repo` gitlink。配置不联网，依赖缺失时报告初始化方法。相邻源码只用于核对。
- Monolithic 使用一份 STATIC flecs，Modular 使用一份 SHARED flecs。同一 World 的全部消费者使用一致头文件、构建宏和实际 runtime。只有 `Source/Runtime/ECS` 定义 `Pangu::ECS`，第三方目标为 `ThirdParty::Flecs`，产物名称遵循平台惯例，仅目录按平台隔离。
- 原生接口写作 `pg::flecs::`，Pangu 集成接口位于 `pg::ecs`。保持原生类型身份和 Borrow 契约，组件允许使用普通 C++ 类型。Module Query 和业务 Catalog 沿用 PanguMetaTool，ECS 登记由业务代码负责。
- flecs 运行库按上游方式以 C 编译。`ThirdParty::Flecs` 通过 PUBLIC 传递 `FLECS_CPP`，ECS 和业务以 C++23 使用官方 `<flecs.h>` 提供的 `pg::flecs::world`（即 `::flecs::world`）和强类型查询。统一启用 `FLECS_CPP_NO_AUTO_REGISTRATION` 和 `FLECS_KEEP_ASSERT`，采用显式顶层组件登记、消费方逐 World 绑定与主线程串行执行。
- 应用通过 `AdditionalResidentQueries` 显式接纳常驻 ECS。World 由 Scope 持有，宿主在父 Scope 实例及模块代码有效时排空全部 World。独立 ModuleManager 路径、外部 Pin 及失败批次的原生释放屏障沿用现行契约。
- 阅读 [C++ 规范](../../../wiki/foundation/cpp-guidelines.md)、[测试维护规范](../../../Tests/README.md)、[构建系统](../../../wiki/foundation/build-system.md)和 [AGENTS.md](../../../AGENTS.md)。运行正式 Preset，Linux 在 WSL 的 CIFS 源目录及 ext4 BuildRoot，macOS/iOS 通过 SSH 使用同一挂载源码及 APFS BuildRoot。Windows/Android 沿用 NTFS BuildRoot。同一 BuildRoot 串行切换模式。

| 输入或状态 | 预期行为与归属 |
| --- | --- |

## 任务 1：EngineHost 先排空 World，再进入 Module 关闭

**接口。** 保留 `EngineHost::BeginShutdown(HostOperationReport&) noexcept -> Status`、`TryFinishShutdown(HostOperationReport&) noexcept -> Status`。新增跨 Runtime 内部桥，供 EngineHost 调用。

```cpp
namespace pg::module::detail
{
class ModuleHostShutdownAccess final
{
public:
    [[nodiscard]] static PG_MODULE_API Result<bool> BeginWorldShutdown(ModuleManager&, ModuleOperationReport&) noexcept;
    [[nodiscard]] static PG_MODULE_API Status TryFinishWorldShutdown(ModuleManager&, ModuleOperationReport&) noexcept;
};
} // namespace pg::module::detail
```

`ModuleHostShutdownAccess` 为 `ModuleManager` 的 friend，两个入口在 `ModuleManager.cpp` 复用操作防重入与报告发布。对应的私有运行时接口为 `ScopeRuntime::BeginWorldShutdown(ModuleOperationReport&) -> Result<bool>` 和 `ScopeRuntime::TryFinishWorldShutdown(ModuleOperationReport&) -> Status`。Begin 返回 `true` 表示仍有 World，返回 `false` 表示可直接进入 Module Begin。TryFinish 成功表示本宿主所有 World 已退休。
