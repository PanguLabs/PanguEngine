# 嵌套测试构建第一轮优化

状态：已实现并完成 Windows Full、Linux/macOS 定向验收；Android/iOS 本轮未重新运行。

## 目标与范围

在 `perf/nested-test-builds` 分支优化 Windows 嵌套测试构建的并行预算与调度。现有基线为 Windows Release/Modular Full 315/315 通过，CTest 2149.78 秒；其中 30 项 `requires.nested-build` 合计 2003.12 秒。宿主有 12 个逻辑处理器。

第一轮保留全部测试场景、断言、运行集合及资源锁。第二轮才评估模式矩阵和夹具重复构建的收缩，本轮不实施。

## 方案与选择

- 仅提高外层 CTest 并行度：改动小，但内层默认预算和共享资源仍会限制效果。
- 统一预算传递、补齐命令计时，测量后选择内外层预算：用户选择此方案，能先保持覆盖并测出调度收益。
- 同时精简矩阵和夹具：可能减少总工作量，但需另行证明等效覆盖，留待第二轮。

## 行为约束

- 显式 `PANGU_TEST_BUILD_JOBS` / 已有 cache 优先；未指定的子配置继承父测试预算，完全未设置时保留默认 2。预算拒绝零、负数及非整数。
- CTest 为嵌套构建设置与 `PROCESSORS` 对应的环境预算，子配置、宿主工具构建和内层 CTest 不得重新采用无关默认值。
- 现有聚合构建外层 `--parallel 1` 保留，避免外层目标与内层构建并发相乘。
- 共享宿主引导在无输入变化时保留工具时间戳，避免另一原生图破坏已完成图的 no-op；真实登记输入变化仍完成一次失效处理。同一工具的内层 CTest 组使用工具级资源锁保护共享发现目录。
- 在既有测试辅助脚本记录配置、构建、发现、运行的命令耗时；日志位于对应 BuildRoot，不修改子命令输出和失败判据。
- 比较代表性慢测在 2、4、6 并行下的耗时与进程树内存峰值，选择测量支持的 Windows 设置。外层候选预算为 8；保留 `PanguMetaHostBuild` 与宿主工具文件锁。
- 正式 Project 测试在干净的已提交源码、override OFF 上运行，测试运行期间不修改共享 tracked 文件与 HEAD。

## 验收

扩展现有 TestInfrastructure 回归验证非默认预算的真实子配置与内层测试行为，先观察失败再修复。定向验证通过后进行代表性测量、Windows Full 和分支只读评审，记录首次失败、重跑及未验证平台。Windows 优化验收后补充 Linux/macOS 的 TestInfrastructure、Meta 增量、模式切换及 Project 切换定向验证，各项结果仅代表实际执行的配置和范围，不扩展为其他平台的全量或移动设备运行证据。
