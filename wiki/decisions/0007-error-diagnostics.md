# ADR-0007：错误值、失败报告与基础诊断分离

> Status: Accepted
> 日期：2026-10-21
> 权威规范：[错误处理与基础诊断 v1](../foundation/error-diagnostics.md)

## Context

PanguEngine 已确定禁用 C++ Exception，采用显式错误传播，并允许受控 C++ Module 交互及安全卸载。将字符串、原因链或插件回调放入默认错误对象，会增加 OOM 处理、析构及代码驻留的复杂度；仅依赖普通日志，又会在拥塞或输出故障时丢失重要失败现场。

诊断设施必须服务启动、运行和清理阶段，但不能成为 Fatal/OOM 处理的前置依赖。实时业务也不能因日志输出阻塞或无界扩容而失去响应。

## Decision

1. 默认 Error 是无堆分配的结构化值，以稳定错误域、代码和可选原始错误码表达失败；公共可失败接口采用 `std::expected<T, Error>`，无成功载荷时使用其 void 形式。Result 不自动承诺 OOM 可恢复。
2. 重要操作提供独立于普通日志的有界失败报告，由操作入口拥有并显式向下传递上下文；Error 不持有报告指针或关联句柄。交付后的报告拥有所需内容，可独立于 Host 和原始 Plugin 存活。
3. 保留主错误，清理失败作为次要诊断；异步子报告在完成或排空后归并，取消不提前销毁存储，也不覆盖原始失败。多个独立失败由父操作按声明规则选择主错误。
4. Assert 可在 Shipping 移除；Check 在所有配置下有效；启用时两者失败都进入 Fatal，不提供忽略后继续的通用机制。Fatal 是独立的进程终止路径，不依赖普通日志或正常 Host Shutdown。
5. 普通诊断由明确的 Host 实例配置并拥有固定预算。实时业务默认有界异步提交，不执行可能阻塞的 Sink I/O；同步输出是显式选项。优先保留 Warning/Error，容量仍不足时允许丢弃并统计，不承诺可靠送达。
6. Diagnostics 初始化明确支持可恢复 OOM。失败默认降级为应急诊断；显式要求某项报告保存能力的运行模式，在该能力失败时正常回滚启动。v1 Sink 实现代码在 Diagnostics 整个生命周期内驻留，可独立卸载的 Plugin Sink 延后。
7. 正常关闭默认排空日志；Flush 以调用时确定的已接受记录范围为界，不等待后续新记录，并报告范围内丢弃和 Sink 失败，不承诺持久落盘。超时或在途调用不能通过强制销毁伪装为成功。

此决策冻结设计语义，不冻结示意 API 的名称、布局或平台实现，也不承诺多个 EngineHost 同时运行已获支持。

## Alternatives

- **统一全局错误枚举或裸整数**：表示简单，但容易混淆领域，并使扩展依赖统一枚举维护；采用稳定错误域加域内代码。
- **默认富错误对象**：携带文本与原因链更方便，但扩大传播成本和生命周期义务；保留为显式领域报告，不进入默认 Error。
- **普通日志可靠送达**：需要阻塞、额外存储或可靠持久化协议；采用有界尽力输出，并用独立失败报告保障重要操作的现场。可靠保存需求另行声明。
- **v1 支持动态插件 Sink**：增加撤销、在途调用与代码驻留协调成本；先限定 Sink 代码驻留，Plugin 产生日志不受此限制。

## Consequences

- 错误判断、失败现场与日志输出分别具有清晰的所有权和失败保证；可单独测试，不要求错误传播先启动 Diagnostics。
- 重要操作需要显式预算和传递报告，异步操作还须处理子报告归并；不会自动获得无限原因链或跨线程最早失败顺序。
- Diagnostics 初始化必须避免隐式致命分配；运行期必须处理背压、丢弃统计和 Flush 完成范围。
- 本决策补足既有 C++、Memory、Service 原则，不替代它们；规范、索引及总体架构同步更新。平台探针和正式回归测试仍须按权威规范验收。

## Open Questions

错误域身份编码与发放、Native Code 布局、具体公共 API、报告与日志容量、优先保留和队列算法、Flush 范围及统计实现、各平台应急输出与终止入口、CMake Target 归属。多 Host 并行运行与可独立卸载的 Plugin Sink 需要后续专项设计。
